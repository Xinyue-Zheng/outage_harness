# Harness implementation report, 2026-10-06

Written for: the project owner, before the move into the internal environment.

This report covers the state of the outage investigation harness in this repository
after the session of 2026-10-06. Everything here runs on synthetic data. The decision
model and the verifier model are real models on a local vLLM endpoint
(Qwen2.5-32B-Instruct-AWQ). Nothing has run on real data or on the internal endpoint.

## 1. What changed in this session

| Change | Why |
| --- | --- |
| LangGraph removed; `loop.py` is a plain loop over the same twelve nodes | The internal environment cannot install the package. The nodes, edges and conditional branches are unchanged; a `while` loop with a `match` on the node name replaces the graph. The LangGraph SQLite checkpoint is gone; the Step file was already the checkpoint. The tracing refusal is gone with it. |
| MCP removed; `data_tools.py` is a tool library, `data_client.py` the client over it | Same reason. `DataClient` keeps the two methods the loop used (`list_tools`, `call` with a timeout). `LocalClient` runs tool functions in this process with the same typed results: rows, timeout, failure. Rows pass through JSON on the way back, so a local tool returns exactly what a remote one would. |
| A finish decision lists the key areas it leaves unqueried in its gap `targets`; the `question` gives the reason | The old rule looked for area ids inside the question text. The model never used it and queried every area instead. Targets make the rule mechanical and reuse the field the model already fills. |
| The context shows, for every key area with unqueried locations, how many of them border a queried location where D0 is present | The program fact a skip reason can rest on. An area with zero bordering locations can be left unqueried; one with more than zero also fails the boundary rule. The model used this correctly in the first live run after the change (run E: it named S2, S3, F8 and W1 with the reason "insufficient budget"). |
| A budget that can no longer cover the cheapest key area bordering D0 ends the run as `query_budget` | Found in live runs C and D: the boundary rule required F6 and F7, the budget forbade them, and the model repeated the refused query until the rejection cap. The program now recognizes the dead end: a refused finish, or a query refused for budget, ends the run with the typed reason. The context announces it one round ahead. |
| New rejection kind `budget_exceeded` | Budget refusals were labelled `precondition_unmet`. The loop guard needs to tell them apart. |
| Verifier instructions: judge the question, not the result it has not produced | In runs A and B the verifier objected to `impact.estimate` because "impact has not been computed", which is what the action does. The instruction now says so, and tells the verifier how to judge a finish's skipped areas. |

Dependencies: none beyond the Python standard library. Development tools: Ruff and ty.
Python 3.12.12 pinned. 72 tests, 1 skipped unless a model endpoint is configured.

## 3. Live runs on the 32B model

All runs: Qwen2.5-32B-Instruct-AWQ for both model nodes, temperature 0, step cap 30,
boundary share 0. "Condition B" adds the last three steps to the context.

| Run | Budget | Condition | End | Rounds | Rejections | Queried | Note |
| --- | --- | --- | --- | --- | --- | --- | --- |
| before this session | 1,600 | A | `rejection_cap` | 11 | 5 | 1,549 | the implementer's run; budget spent on F2 early |
| A | 2,400 | A | `complete` | 10 | 1 | 2,400 | completes by querying every area |
| B | 2,400 | B | `complete` | 8 | 1 | 2,400 | same |
| C | 1,600 | A | `rejection_cap` | 12 | 5 | 1,575 | finish named F6, F7 as safe; boundary refused; budget blocked F6, F7; loop until cap |
| D | 1,600 | B | `rejection_cap` | 10 | 5 | 1,556 | same dead end |
| E (after the budget rule) | 1,600 | A | `query_budget` | 6 | 1 | 1,526 | finish refused on boundary and backup_load; program ends the run with the typed reason |
| F (after the budget rule) | 1,600 | B | `query_budget` | 9 | 4 | 1,526 | a budget-refused query with the boundary blocked ends the run |
| G (after the budget rule) | 2,400 | A | `complete` | 9 | 1 | 2,400 | unchanged where the budget is not binding |

What the runs show:

- The loop, the registry join, parsing, validation, the verifier, execution, State
  update, Step writing, the caps and the completion checks all run end to end with a
  real model. Every run ends with a typed reason.
- With the budget not binding, the model completes by querying everything. It does not
  reason about where D0 can be; it clears the key-area list. This is a strategy
  question for the experiments, not a harness defect.
- With the default budget, the model spends on far areas first (F1, V1, F3, F4 in round
  one) and then cannot afford the areas that still border D0. The old outcome was a
  loop to the rejection cap; the new outcome is `query_budget` within a few rounds,
  with the reason in the Step and in the context.
- Run E's finish shows the new rule used as intended: targets S2, S3, F8, W1, reason
  "insufficient budget". The boundary rule still refused it, correctly, because S2
  borders D0. The program then ended the run instead of waiting for the model.
- Recurring model faults, all handled: an impact decision with no gap targets (rejected,
  then corrected the next round); a KPI query with a bad parameter; one unparseable
  reply; one repeated identical impact decision after a wrong verifier concern.

Example run E is in `examples/live_qwen32b_budget1600/` as text: the exact inputs sent to
the model, its replies, the rendered contexts, `run.json`, `trace.json`, and a step
summary with every decision, validation result, review and note.

## 4. What the program guarantees now

- Every round leaves one Step with the decision, the validation result, the review, the
  Observation, the State before and after, the counters and the versions.
- Every model reply becomes either an accepted decision or a fact in State; nothing
  crashes the loop. Transport failure of the model endpoint is the one exception: the
  run stops with an error.
- Every tool call ends in an Observation with a status; a timed-out or failed member
  does not lose the others.
- The run ends only with a typed reason: `complete`, `step_cap`, `query_budget`,
  `time_cap`, `retry_cap`, `rejection_cap`, `repeated_query`. Ended is never confused
  with complete.
- The model's view and the validator's rules come from one registry.

## 6. How to run

```bash
uv sync --locked
uv run ruff format && uv run ruff check --fix && uv run ty check
uv run python -m unittest discover -s tests -v
uv run python -m outage_poc --output outputs/run_01 --maps \
    --base-url http://127.0.0.1:8012/v1 \
    --model qwen2.5-32b-instruct-awq --verifier-model qwen2.5-32b-instruct-awq
# condition B: add --recent-steps 3; full budget: --query-budget 2400
# regression without a model for the decisions: --script tests/scripts/complete.txt
```

Reference runs and ground truth for the outage investigation

Three things, each a block diagram: the rule-based investigation that replaces the model with fixed rules and produces the reference extent; the ground truth that adds the during-outage KPI; and how a harness run is scored against them.

1. The rule-based investigation

It is the harness loop with one block swapped. Every other block is the one the harness already runs; the model's seat is taken by a fixed policy that reads the completion check and answers with one action. No text is rendered for anyone; the policy reads the check's fields directly.

Termination: every round either fetches new locations or expands the study area; both are bounded by the frame and the activity areas inside it. A cost cap per site ends the run as a cap, as in the harness, and the reference is then marked incomplete.

2. The ground truth

Two halves, from two sources. The coverage half comes from the reference run above: where the outage sectors cover, which backups are co-observed at each location, the classes by signal. The congestion half comes from the KPI of the outage interval itself, which the investigation may never read: the PRB each backup cell actually carried while the site was down. The second half turns the predicted capacity classes into observed ones and is what the redistribution model is refined against.

The two halves, exactly

  • Coverage truth, per activity location in the reference footprint: the outage sectors listed at or above -110 dBm; the eligible backups co-observed in the same sample with their RSRP; the signal class (no backup; backup weaker by more than the margin or below the threshold; adequate backup). It is the reference extent and needs no outage-time data.
  • Congestion truth, per backup cell and per outage hour: the PRB it actually carried during the outage, from the same KPI tool with the outage window as the query window, which the investigation is forbidden to use. A backup is congested in an hour when its observed PRB exceeds the limit. The capacity class of a location follows from its strongest co-observed backup's observed PRB in the worst hour. The ground-truth report is the final-report format with these classes in the capacity column instead of the predicted ones.

Two caveats the ground-truth file states on its own first lines: the observed PRB is what the backups carried given everything that happened in that hour, not only the moved traffic, so a congested backup may be congested for another reason; and a site whose outage was cancelled or shortened has no congestion truth for the missing hours, which the file marks as unknown rather than filling.

What it gives the redistribution

For every backup cell and hour the file holds the predicted PRB (baseline plus transfer) next to the observed PRB. Across the refinement set that is a regression target: the transfer rule (softmax by RSRP), the demand weights per area kind, and the thresholds can be refit to minimize the error, and the held-out set says whether the refit generalizes. That is the first concrete piece of the offline refinement, and it needs no model.

3. Scoring a harness run

Every run, any condition, is scored against the same two files with five numbers. The first four are correctness; the fifth is cost. None of them is the completion check, which stays a property of the run, not a score.

The rule-based run is also scored by the same numbers against the ground truth, so it appears in every table as the no-model condition. If it scores as well as the rendered run at the same cost, the model's contribution is not in correctness and the paper says so; if it costs more, the model's contribution is the order and the resolution of the queries.

4. Implementation, in order

  1. --policy rules on the rendered package's run script: replaces the model call with the rule policy and switches off the verifier; everything else is shared. Adds calls.json with latency per call (both policies).
  2. make_reference.py <site> <window>: runs the rule policy with the verification pass and the cost cap, writes reference_extent.json, reference_report.md, calls.json.
  3. make_ground_truth.py <reference dir>: queries the during-outage KPI for the outage sectors and the co-observed backups, writes ground_truth.json and ground_truth_report.md, with the predicted-versus-observed table per backup and hour.
  4. score_run.py <run dir> <reference dir>: the five numbers, written as score.json next to the run.
  5. Run 1 to 4 on the one closed case; score the four existing runs (rendered, concat, concat_checked, rules). Then the 90 sites, 60 refinement and 30 held out, split before any refinement.

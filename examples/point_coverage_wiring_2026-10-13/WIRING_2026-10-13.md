# Per-point coverage wiring, 2026-10-13

The heatmap tool returns one serving sector per sampled coordinate. It cannot
show which other cells cover a location, so the State could never say whether
a backup cell exists where the down cell serves. The point API returns, for
every sample near a queried coordinate, the serving sector and the strongest
neighbour cells with RSRP. This folder wires that API into the internal
LangGraph harness with the smallest change to the model-facing interface:
the LLM still names an area id; the program turns the area into grid
locations, calls the point API once per location, stores the raw samples, and
folds them into State.

Everything here was run end to end on a synthetic case (`run_demo.py`), not
on the internal data.

## Files

| File | Role | Replaces |
|---|---|---|
| `point_coverage.py` | fetch an area through the point API, fold the artifact into State, per-area summaries, inspection rows | `evidence_state.apply_coverage`, `_summary`, `_refresh`, `inspect_coverage` for coverage |
| `context_builder_point.py` | the context builder for the new summaries; same `build_context(state, tools, feedback) -> Rendered` contract | `context_builder.py` |
| `runner_point_nodes.py` | the declaration, budget, validate, execute, update and inspect pieces for the runner | the `query_area_coverage` branches in `langgraph_runner.py`, `runner.PARAMETERS`, `policy.RunLimits/RunGuard` |
| `synthetic_case.py` | synthetic geometry, State 0 and a fake point API in the sample's shape | test only |
| `run_demo.py` | runs State 0, two area queries, one inspection, and renders the context after each | test only |
| `test_node_sequence.py` | replays validate -> execute -> update_state exactly as the internal nodes call the pieces, with the internal helpers copied verbatim; runs the internal gap checks and completion check on the result | test only |
| `test_support/outage_harness_langgraph/` | test double of the internal `radio` helpers and the skill resource | test only; use the real package inside |
| `demo_run/` | the output of `run_demo.py`: geography, states, artifacts, contexts | example |

Run the demo with any Python 3.12:

```
python run_demo.py demo_run
```

## Data flow

```
LLM decision: {"action": {"function": "query_area_coverage", "parameters": {"area_id": "S1"}}}
   |
validate_node ...... area exists; cost = unqueried locations of S1; cost <= budget remaining
   |
execute_tool_node .. fetch_area_points(state, "S1", run_dir, query, radius_m, call_id)
   |                   for each grid id of S1 not in the coverage table:
   |                     lat, lon = grid_center(geometry, grid_id)
   |                     samples = query_point_coverage(lat, lon, radius)   <- one API call
   |                   artifacts/step_NN_S1.json  (raw samples per location)
   |
update_state_node .. apply_point_coverage(state, observation, run_dir, is_outage, eligible_backups)
   |                   coverage[grid_id] = {status, observation, area_ids, sample_count,
   |                                        samples: [{serving, cells: {cell: rsrp}}],
   |                                        cells: {cell: {sample_count, serving_count, rsrp min/max/mean}}}
   |                   summaries[area] = counts (below); cells_seen, outage_cells, backup_candidates, unknowns
   |
render_context ..... build_context(state, tools)  -> prefix (fixed) + variable part
```

### Point status

| Situation | Status | In State |
|---|---|---|
| API returned one or more samples | valid | entry with samples and cells |
| API returned an empty list | missing | entry without cells; a later valid result replaces it |
| API call raised or returned a non-list | error | no entry; the location stays unqueried; count in the observation record and a `query_failed` note |

A location that is already in the table is not fetched again, so overlapping
areas (S1 inside study_area, the road corridor through S1) cost nothing twice.

### Per-area summary

Every count is over analysis grid locations of the area.

| Field | Meaning |
|---|---|
| total, queried, unqueried, valid, missing | as before |
| no_coverage | valid locations whose samples list no cell |
| down_cell_present | valid locations where some sample lists an outage sector |
| down_cell_with_backup | of those, locations where some sample lists an eligible backup cell |
| down_cell_with_backup_same_sample | of those, locations where one sample lists both the outage sector and a backup |
| down_cell_without_backup | down_cell_present minus down_cell_with_backup |
| other_cells_only | valid locations with cells but no outage sector |
| boundary, boundary_missing, boundary_with_down_cell | queried locations with an unqueried 4-neighbour in the same area |
| outage_cells, backup_candidates | the cells of each kind seen in the area |
| cells[cell] | present, serving, strongest, with_down_cell (same sample), sample_count, RSRP min/max/mean |

The context line the counts feed:

```

  Of those 21 locations, 6 also list an eligible backup cell (6 in the same sample as the

  CCSN000004_aa_1 (not an eligible backup: other technology): present at 9 valid locations, ...
```

## Wiring steps inside

1. **Client.** Keep `query_point_coverage(lat, lon, r, token)` as it is. In the
   runner, build the callable once per run:
   `query = make_point_query(query_point_coverage, token, radius_m)`. The token
   and the base URL stay in configuration; neither reaches State or the model.
2. **Declaration.** Replace the `query_area_coverage` declaration with
   `QUERY_AREA_COVERAGE` (area_id only). Remove `query_coverage_heatmap` from
   the declarations shown to the model and from `DECISION_SCHEMA`'s function
   enum. Replace the two entries in `runner.PARAMETERS` with `PARAMETERS_PATCH`.
3. **Budget.** Add `max_query_locations` to `RunLimits`, `queried_locations`
   plus the two methods to `RunGuard` (both in `runner_point_nodes.py`).
   Add `query_budget` to State 0 (`{"locations_spent": 0, "locations_limit": N}`)
   so the context shows the budget line.
4. **validate_node.** Replace the `query_area_coverage` block with a call to
   `validate_query_area_coverage(arguments, state, run_dir, guard)`. Replace
   `inspect_coverage` with `inspect_point_coverage`.
5. **execute_tool_node.** Replace the `query_area_coverage` block with
   `execute_query_area_coverage(state, arguments, run_dir, step_index, query, guard)`.
   The bounding-box code and the `query_coverage_heatmap` call go away.
6. **update_state_node.** Replace the coverage branch with
   `update_state_query_area_coverage(state, observation, run_dir, guard)`.
   `_update_state` still runs first for the compact observation list.
7. **Context builder.** Replace `context_builder.py` with
   `context_builder_point.py` (same function name and contract). It reads only
   State; the skill resource and the radio helpers come from the internal
   package as before.
8. **Skill text.** The sentence in `investigation_skill.txt` that explains
   coverage queries must say: one point call per grid location, samples list
   the serving sector and strongest neighbours, cost is counted in locations.
   The internal skill is not in this folder.
9. **Gap checks.** `gap_checks.py` needs no change: it reads `summaries[area]`
   counts and `cells_seen`, both still produced. The rule "targets must be
   among the queried areas" is already there.

## Open gaps

These need a decision or a fact from the internal side before the first real run.

1. **Radius versus grid spacing.** The demo uses 100 m spacing and a 50 m
   radius: the inscribed circle, so corners of a grid cell are never sampled
   and samples are never shared between neighbours. A radius of spacing / sqrt(2)
   covers the whole cell but double counts samples near edges. Measure how many
   samples the API returns per call at the chosen spacing; if most calls return
   zero, the grid is too fine for the API's sample density, and the spacing
   should grow before the radius does.
2. **Time window of the samples.** The stub takes no time parameter. The
   harness assumes coverage samples describe the pre-outage network. Confirm
   what period the API aggregates over; if it includes post-outage time, the
   evidence is contaminated and the tool needs a window parameter.
3. **Top-N truncation.** A sample lists the serving sector and at most N
   neighbours. A cell missing from a sample is "not among the strongest N",
   not "absent". The context and the unknowns say this now, but the completion
   check "sector absent in a farther area" reads `cells[cell].present == 0`
   and treats absence as evidence. Either keep that reading and state it as an
   assumption, or require the sector to be absent at locations where fewer
   than N cells are listed.
4. **Cost and latency.** One API call per location, with a (15, 300) second
   timeout each. A 300-location area at 1 s per call is 5 minutes sequential.
   `POINT_WORKERS` runs calls in parallel; set it from the API's rate limit.
   `max_time_seconds` in `RunLimits` (300 s today) must grow, or the first
   query ends the run as time_cap.
5. **Cell id format.** The summaries key cells by `sector_name`. The KPI tools
   take `cell_ids`. Confirm that KPI tables use the same sector-name format
   (`xxxxx_aa_1`); if they use the numeric `id` from the sample, the artifact
   keeps both and the table needs a mapping.
6. **Backup eligibility.** `eligible_backup_cells` from the internal `radio`
   module decides who counts as a backup (same technology, not an outage
   sector). Verify it accepts the sector-name format; the test double here
   uses the regexes from `policy.py`.
7. **Per-sample RSRQ and RSSI.** The sample's `rsrq` and `rssi` belong to the
   serving sector only. They stay in the artifact and are not folded into the
   table. If RSRQ is needed for backup eligibility later, it exists only for the
   serving cell.
8. **Boundary rule in completion checks.** The summaries now carry boundary
   counts, but `completion_evidence_status` still uses the distance-based
   rule. Switching to the boundary rule (no outage sector on the query boundary
   of the study area) is a separate decision.
9. **Heatmap as a cheap scan.** The old tool can stay as a second action that
   returns the strongest cell per point over a rectangle at low cost. It would
   answer "where is the outage sector the strongest", not "which cells overlap".
   It is removed from the model's action list here; adding it back is a new
   registry entry with its own result kind.
10. **Style.** These modules follow the internal code's dict-based style
    (`dict[str, Any]`), not the typed dataclass style of `outage_harness`. They
    are drop-in for the internal runner; they are not a template for new code
    outside it.
